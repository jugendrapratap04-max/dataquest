## 1. Verdict

This is a real product, not a prototype. Auth, in-browser Python and SQL,
server-side re-verification of every submission, derived (not seeded) progress,
83 lessons, 156 graded problems, 40 interactive visualisations, study rooms with
server-enforced rules — all working, all verified today. `npm run build` passes
clean, `npm run db:check` passes clean, the live site serves every route.

Three things stand between it and being genuinely good:

1. **One critical security hole** that is live right now (§2).
2. **The teaching quality is Python-only.** 35 of 83 lessons meet the project's
   own bar. All 35 are in the Python track. The other 8 tracks are prose stubs (§4).
3. **Almost nobody can find it, and almost nobody who signs up starts.**
   14 real signups, 2 of whom ever opened a lesson (§5, §6).

## 2. CRITICAL — submitted Python can read the server's secrets

**Status: live in production today. Fix before anything else.**

`lib/verify.ts:51` calls `loadPyodide({ indexURL })` without a `jsglobals`
option. Pyodide's documented default for `jsglobals` is `globalThis`, so the
Python `js` module inside the *server-side* verifier is wired straight to the
Node process's global scope.

Reproduced locally on 2026-07-29 with `scratchpad/rce-test.mjs` (since deleted):

```python
import js
leak = js.process.env.DQ_CANARY      # -> "SECRET-CANARY-12345"
js.require("child_process")          # -> blocked ("require")
```

The canary came back. `require` did not resolve, so this is not full command
execution — but reading `process.env` is enough on its own. On Vercel that
environment holds **`AUTH_SECRET`** and **`DATABASE_URL`**.

Failure scenario: anyone signs up (signup is unthrottled), submits a solution
whose body is `import js` plus an outbound `js.fetch(...)`, and walks away with
the session-signing key — which forges any user's cookie — and the Neon
connection string, which is the whole database.

**Fix:** pass an empty `jsglobals` to `loadPyodide` in `lib/verify.ts`, then
re-run the same canary test to prove it is closed. One line. Do this first.

## 3. High-priority bugs (verified in code)

| # | Issue | Where | Why it matters |
|---|---|---|---|
| H1 | Verifier has no timeout or interrupt buffer | `lib/verify.ts` | `while True: pass` wedges the serverless function for every other user |
| H2 | Double-XP race | `app/api/submit/route.ts:35-68` | Read-then-increment with no transaction; `Submission` has no `@@unique([userId, problemId])` — 20 concurrent submits of one correct answer pay 20× XP |
| H3 | Signup completely unthrottled | `app/api/auth/signup/route.ts` | Login is rate-limited, signup is not; each request costs a scrypt hash and a row |
| H4 | Login throttle does not survive serverless | `lib/rate-limit.ts:18` | In-process `Map`; Vercel spreads requests across instances so the counter never reaches the limit |
| H5 | Account enumeration | signup returns 409 "already registered"; login short-circuits before scrypt | Both confirm whether an email exists |
| M6 | `Submission` has **no indexes at all** | `prisma/schema.prisma:112-121` | It is queried by `userId` on nearly every authed page render; `getStreak` reads every passing submission a user has ever made |
| M1 | Eight routes 500 on malformed JSON | `req.json()` with no `.catch()` in login, signup, feedback ×2, notes ×2, progress, submit | `curl -d 'x'` → unhandled rejection |
| M2 | Raw client values go into Prisma `where` | `submit:30`, `notes:28`, `feedback:50` | `{"id":{"not":""}}` on notes DELETE wipes all of the caller's notes in one request |
| M3 | `/api/progress` trusts any `lessonId` and `status` | `app/api/progress/route.ts:9-19` | Any lesson can be marked complete without reading it; certificates gate purely on percentage |
| M5 | Logout does not revoke the session | `app/api/auth/logout/route.ts:7` | Stateless token stays valid 30 days after "log out" |

### The answers ship to the browser

`app/(app)/practice/[slug]/page.tsx:77-81` passes the full `tests` array —
arguments **and expected values** — to the client. Confirmed in the live HTML of
`/practice/add-two`: `"expected":7`, `"expected":8`, `"expected":0`.

The server re-run grades against those same values, so a student can read the
expected outputs from the page source and hardcode them. The paste-blocking in
the editor is decorative against this. Not urgent — but worth knowing that
"server-verified" currently means "verified against answers the student can see".

## 4. Content — the real picture

`npm run syllabus` reports "4 lessons not at standard, out of 39". That number
only ever looks at the **Python track**. Measured across all 83 lessons against
the project's own bar (≥400 words, ≥1 visualisation, ≥4/5 teaching blocks):

| Track | Lessons | Problems | Quizzes | At standard |
|---|---|---|---|---|
| 1 Python | 39 | 89 | 35 | **35** |
| 2 Statistics | 11 | 19 | 0 | 0 |
| 3 NumPy & Pandas | 6 | 27 | 0 | 0 |
| 4 Data Visualization | 5 | **0** | 0 | 0 |
| 5 SQL | 6 | 18 | 0 | 0 |
| 6 BI & Dashboards | 3 | **0** | 0 | 0 |
| 7 Machine Learning | 6 | 3 | 0 | 0 |
| 8 Deep Learning | 3 | **0** | 0 | 0 |
| 9 Deployment & Job Prep | 4 | **0** | 0 | 0 |
| **Total** | **83** | **156** | **35** | **35 (42%)** |

- Every lesson in tracks 2–9 is **48–129 words** with none of the teaching
  blocks — no hook, no definition, no analogy, no mistakes, no interview
  questions, no quiz. Smallest: `deploy-portfolio` at 48 words.
- **44 of 83 lessons have neither a practice problem nor a quiz** — pure prose.
- The "Data Visualization" track has **zero interactive visualisations**, despite
  being the visualisation track. All 40 viz components are Python (36),
  Statistics (3) and Pandas (1).
- **48 of 134 syllabus topics have nothing covering them**, including all 13 DSA
  topics (Big-O, stacks, queues, linked lists, hash tables, trees, graphs,
  searching, sorting) and all 7 reference pages. DSA is the interview-critical
  block and it does not exist.
- Difficulty is bottom-heavy: **96 Easy, 36 Medium, 16 Hard, 8 Super Hard.**
  Every one of the 56 inline Python problems is Easy.
- **XP does not scale with difficulty for 33 problems.** The `EX()` helper in
  `prisma/seed.mjs:3670` hardcodes 20 XP, so a Super Hard problem pays the same
  as an Easy one. The SQL and pandas modules scale 20/30/40 correctly — this is
  an inconsistency, not a design decision.
- All 33 `extraProblems` share `order: 50`, so their ordering inside a lesson is
  undefined (9 problems all at 50 for `strings`).

**No orphaned code:** all 40 viz components are registered and each is used
exactly once. No broken syllabus references. No TODO/FIXME markers anywhere in
the source.

## 5. Nobody can find the site — no SEO at all

The only realistic growth channel for a free learning platform is search, and it
is switched off:

- **`/robots.txt` → 404. `/sitemap.xml` → 404.** Neither file exists.
- **All 83 lesson pages share one `<title>` and one meta description** — the root
  layout's "Etudo — Learn. Practice. Get Job-Ready." Verified live on
  `/learn/loops`. To Google, 83 pages look like 83 copies of the homepage.
- Only `/book`, `/book/[track]`, `/guidelines`, `/terms` and `/privacy` define
  their own metadata. The lesson pages — the actual content — do not.

This is the highest-leverage fix in the whole document relative to effort: a
`generateMetadata` in `app/(app)/learn/[slug]/page.tsx`, a `sitemap.ts` and a
`robots.ts`. The lessons are already public and server-rendered, so they are
ready to be indexed the moment they are described properly.

## 6. Usage — what the production database actually says

Queried Neon on 2026-07-29.

| | |
|---|---|
| Total accounts | 15 (1 seeded demo + 5 fake leaderboard + **14 real signups**) |
| Real users who ever opened a lesson | **2** |
| Real users who ever submitted code | **2** |
| Total submissions, all time | **8** (7 passed) |
| Notes written | 5 · Feedback rows | 1 ("Needs improvement") |
| Study rooms created | 14 · sessions 17 · room messages 4 |

Signups are arriving (real Gmail addresses, 2 as recently as 27 July) and then
nothing happens. **12 of 14 never opened a single lesson.** That is the product's
central problem — not content volume, not features.

Two contributing causes are visible in the code:

- **Signup lands on `/dashboard`** (`components/AuthForm.tsx:43`), not on the
  first lesson. The dashboard's resume card does say "Continue where you left
  off" and links to lesson 1 — but a brand-new user is shown a progress
  dashboard with nothing in it, one click before anything worth doing.
- **Guest search is dead.** `/api/search` returns **401** to signed-out visitors,
  and the topbar search box is rendered for them anyway — it just says "Nothing
  found". Confirmed live: two 401s fire on every page a guest loads.

### The leaderboard is dishonest

`app/(app)/leaderboard/page.tsx:24` takes the top 25 users by XP with no filter.
The five seeded accounts (`rohit@dq.dev` and friends) hold **1450–3940 XP and
have never made a single submission**. A real student with 20 honest XP ranks
below five people who do not exist.

This is the same trap as the fake streak and the seeded `Track.status` — both
already found and removed for exactly this reason. It is the last one left.

## 7. UX and structural gaps

- **No `not-found.tsx` and no `error.tsx` anywhere.** Four routes call
  `notFound()`. A bad slug or any server error renders Next's bare 404 — no nav,
  no sidebar, no link home. The browser back button is the only way out.
- **`/projects` is a shell.** 31 lines, a hardcoded 6-item array, every card
  stamped "Coming soon", nothing clickable. It is in the sidebar with the real
  features.
- **Voice chat is built and unreachable.** 457 lines of working WebRTC, gated to
  rooms whose host is `ADMIN_EMAIL`. Every other room shows "in testing".
- **Theme locks are dead code.** `components/Topbar.tsx:30-36` unlocks every
  theme at `xp:0` for the beta; the lock, toast and coin-cost UI can never fire.
- **`/feedback` has zero inbound links** — the admin has to type the URL.
- **Resume builder does not persist.** Client state only, seeded with fake
  placeholder content ("Jugendra Pratap", an 88%-accuracy churn project). Close
  the tab and it is gone.
- **Landing page stats are hardcoded** at 82 lessons / 156 problems
  (`app/page.tsx:105-106`). The database says 83. It will drift further.
- **The activity heatmap and the streak disagree** — `getActivity` counts all
  submissions, `getStreak` counts only passing ones.
- **Mobile is mostly good** (verified: no horizontal overflow on the lesson page
  at 375px), with a 900px drawer breakpoint and a `prefers-reduced-motion`
  kill-switch. Untreated spots: `.pb-row` (fixed 130px label column),
  `.bigcal` (14 fixed columns), `.lnav` (no wrap), and `.learn-side` which hides
  the whole in-module lesson list below 1000px.
- **No form labels are associated with inputs** — `htmlFor` appears nowhere in
  the codebase. Login, signup and the resume builder are unlabelled to a screen
  reader. `RoomsLobby` and `FocusClient` do it correctly, so the pattern to copy
  already exists.
- **Practice page weight:** 1.05 MB on open, of which Monaco is 897 KB. Pyodide
  (9.6 MB wasm) correctly loads only on Run, not on page open.

## 8. Recommended order

Ordered by damage prevented per hour of work, not by how interesting it is.

1. **Close the `jsglobals` hole** (§2) and redeploy. One line. Today.
2. **Filter the fake accounts off the leaderboard** (§6). One line, and it stops
   the product lying to the students who did the work.
3. **SEO: `generateMetadata` on lessons, `sitemap.ts`, `robots.ts`** (§5). Half a
   day, and it is the only thing that changes the signup number.
4. **`not-found.tsx` + `error.tsx`** (§7). Half an hour, removes every dead end.
5. **Fix guest search** — either serve a public index or hide the box for guests (§6).
6. **Send new signups to lesson 1, not the dashboard** (§6).
7. **Submission indexes + the XP transaction + `req.json()` guards** (§3).
8. **Finish the 4 thin Python lessons** — `testing`, `debugging-logging`,
   `clean-code`, `project-git`. Then Python is genuinely complete.
9. **Then choose one:** bring Statistics to the Python standard (11 lessons,
   quizzes, viz), or start DSA from zero (13 topics, interview-critical).
   Both are large. Plan before writing.

Not on this list, deliberately: AI mentor (costs money per message), more
features. The platform does not need more surface area — it needs the surface it
has to be findable, honest, and safe.
